# 旅行工作流与任务路由

默认由当前助手完成研究、决策、排程、表达和自检，不创建额外 Agent，不切换模型。独立工具查询可以并行；职责划分不等于 Agent 拆分。不要把每一阶段变成用户审批关卡。

## 入口与完成条件

| 任务 | 起点与范围 | 本轮完成条件 |
|---|---|---|
| 新旅行 | 读取已有材料 → 约束 → 发现 → 决策 → 核实 → 排程 → 交付 → 验收 | 完成本次要求的深度；关键缺口明确，有推荐与下一步 |
| 目的地／路线比较 | 发现与决策，前置核实会改变选择的硬条件 | 给主张、夜数或适合天数、取舍；无需提前生成完整日程 |
| 酒店／交通专项 | 使用已有路线，比较并核实专项条件 | 推荐与代价清楚，说明对行程的影响 |
| 局部修改 | 读取当前主记录，确定影响范围 | 只处理相关事实与下游衔接，保留其他决策 |
| 行前复核 | 当前订单、动态事实、关键衔接与未完成待办 | 列出变化、冲突、优先行动；无变化不重写全文 |
| 现场调整 | 当前地点、当地时间、剩余硬约束、体力与天气 | 给从现在起可用的短方案和最晚行动时间 |

已有信息足以提出路线骨架、关键取舍或具体阻塞时，先给这个有用结果，再继续已授权研究；不要把“正在处理”算作阶段交付，也不要在证据不足时提前声称可执行。

## 阶段产物与完成条件

| 阶段 | 交给下一步的产物 | 完成条件与回退 |
|---|---|---|
| 约束 | 日期/星期/夜数、出发地、预算、订单、双方核心体验与避开项；区分已知/假设/未知 | 足以比较方向；只问改变判断的问题，缺项只阻塞相关分支 |
| 发现 | 按目的地特点建立候选池与依据，前置路线级硬限制 | 满足专业发现标准，不把首批结果自动定为路线 |
| 决策 | 一个主推荐、取舍及优质未选候选；重大取舍才给A/B | 新信息不再改变选择；不靠固定数量提前停止 |
| 核实 | 入选项和必要备选的目标日期、预约、交通、价格条款、证据和复核触发条件 | 足以执行；核心不可行回决策，普通失败优先同区替代；关键缺口保持草案 |
| 排程 | 同一版住宿、交通、餐饮、参观、休息、预算和待办 | 核算门到门衔接与硬约束；冲突回排程，不伪造更短参观或用餐时间 |
| 交付 | 当前阶段可用的内容、依据与版本，完整规划按请求生成文件 | 质量、事实、衔接和文件检查通过；版式问题只修交付；可先交阶段性提案 |
| 维护 | 新订单、天气、延误或反馈引起的变更及下游影响 | 仅受影响产物失效；跨会话提醒与自动复核须有真实机制和授权 |

## 一份工作记录，按依赖推进

工作记录可直接留在当前上下文或既有主文件，不强制建新文件、数据库或迁移旧行程。进入任务先取主文件身份/版本、约束、已确认安排及相关章节；旧文件无索引时先读目录/标题定位；文件较短、相关内容占大部分或工具不支持分段时直接读全文，不为省字节增加多轮调用。不要为找一条事实遍历整个资料目录。已读且仍在上下文的同版本规则、模板与材料不重复读；上下文缺失或版本不明须重新获取，不能假装记得。

一份记录维护「约束与确认项／候选与取舍／事实证据／选定行程／待办／版本及变化」。专业研究用原结论和证据引用整合，不为格式重做餐饮筛选或文化研究。记录足以恢复工作即可，不输出内部推演；没有变化的阶段不重复总结、重新规划或重新验收。

## 并行查询与集中整合

约束和目标范围明确后，可同时查独立城市的候选、不同场馆规则、已定区域的住宿或相互独立的交通段。只在宿主支持时批量执行；不支持则顺序查询，不声称已并行。默认每批最多 3 个独立查询，遇限流降低并发；这不是候选或研究深度上限。

路线依赖交通可行性、房型依赖酒店筛选、逐日排程依赖开放时间、交付依赖内容定稿，这些有依赖的步骤须先等输入。每个分支返回对象、结论、来源、核验状态和影响；当前助手统一消歧与合并，再集中排程和冲突检查。分支不分别改写主文件，不把未返回当作无结果。

临时网络失败遵守工具重试提示，单个失败请求最多额外重试一次；权限拒绝、无工具、确定无资料或未来未公布不盲重试。可换一个适当来源核实，仍无证据就标缺口并给备选；保留已成功分支。新的证据或查询条件才重开，不因一个失败从头重跑全部研究。

## 变更只使相关产物失效

先标记变化的约束/事实及受影响的城市、日期、交通、预算、待办；沿依赖向下复核，影响跨日就扩大范围。局部修改也不能漏查下游衔接，完整规划中途改条件也不必重做无关城市。用户明确要求全面重新研究时重开发现与核实，但已确认/已订安排仍作为约束；全面研究不代表获准取消或替换订单。

## 局部更新与授权

先展示「改动结果 → 直接影响 → 未决事项」，核对相关交通、预约、费用、住宿与休息。讨论式修改不自动写回，收到更新文档指令再统一保存；本次已明确要求修改文件则直接执行，不重复确认。历史否决项只有新证据或新需求支持时才重新提出并解释。

保护已订锚点；更换真实订单、付款、外发、分享和删除仍需要对应授权。对未能满足的硬约束明确报冲突，不能为了可行而静默修改用户确认的时间。
