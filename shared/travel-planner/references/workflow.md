# 旅行工作流与任务路由

将研究、决策、排程、表达和验收作为职责，不要求不同 Agent。仅有真实工具和适当授权时委派；否则自行完成并如实标为自检。不要把每一阶段变成用户审批关卡。

## 入口与完成条件

| 任务 | 起点与范围 | 本轮完成条件 |
|---|---|---|
| 新旅行 | 读取已有材料 → 约束 → 发现 → 决策 → 核实 → 排程 → 交付 → 验收 | 完成本次要求的深度；关键缺口明确，有推荐与下一步 |
| 目的地／路线比较 | 发现与决策，前置核实会改变选择的硬条件 | 给主张、夜数或适合天数、取舍；无需提前生成完整日程 |
| 酒店／交通专项 | 使用已有路线，比较并核实专项条件 | 推荐与代价清楚，说明对行程的影响 |
| 局部修改 | 读取当前主记录，确定影响范围 | 只处理相关事实与下游衔接，保留其他决策 |
| 行前复核 | 当前订单、动态事实、关键衔接与未完成待办 | 列出变化、冲突、优先行动；无变化不重写全文 |
| 现场调整 | 当前地点、当地时间、剩余硬约束、体力与天气 | 给从现在起可用的短方案和最晚行动时间 |

## 分阶段工作

1. **约束**：整理日期/星期/夜数、出发地、预算、订单、双方核心体验及避开项；标明已知、假设、关键未知。只问会改变当前判断的问题，其余合理假设并继续。
2. **发现研究**：按目的地特点建立候选池，前置核实路线级限制；不要在搜索过程中默认把首批结果定为路线。
3. **比较决策**：按体验价值与旅行成本精选，给一个主推荐；真正存在重大取舍才给 A/B。保留未入选的优质候选及原因。
4. **执行核实**：深查入选项与必要备选的目标日期、预约、交通、价格和条款。核心项目不可行时回到决策；普通项目失败优先同区替代。
5. **排程**：整合住宿、交通、餐饮、参观、休息及预算，核算门到门衔接；时间冲突回到排程，不能伪造更短参观或用餐时间。
6. **生成交付物并验收**：按当前阶段组织内容，完成质量、事实、衔接和文件检查，再展示或保存。阶段性提案也应先自检，不必等全程研究结束才交付。
7. **维护**：新订单、天气、延误或反馈只回退到受影响步骤；跨会话提醒和自动复核须有真实机制及授权。

每步产出可存在同一工作记录中，不要求创建七份文件。保留约束、候选及取舍、关键证据、选定行程、待办和版本；证据摘要只记录结论依据，不输出冗长内部推演。共享信息引用同一主记录，避免多份手抄造成不一致。

## 局部更新与授权

先展示「改动结果 → 直接影响 → 未决事项」，核对相关交通、预约、费用、住宿与休息。讨论式修改不自动写回，收到更新文档指令再统一保存；本次已明确要求修改文件则直接执行，不重复确认。历史否决项只有新证据或新需求支持时才重新提出并解释。

保护已订锚点；更换真实订单、付款、外发、分享和删除仍需要对应授权。对未能满足的硬约束明确报冲突，不能为了可行而静默修改用户确认的时间。
