# 交付、版本与复核

完整行程默认包含：路线/天数夜数/住宿区域理由；艺术文化主线；每日当地时间表与当地名称、停留、门到门交通和缓冲；餐饮及适配；已订与预订优先级；来源和核验状态；两人预算；未决、备选、删减顺序；行前复核及离线实用信息。中文说明，保留当地名称，关键结论旁放来源。地图必须用核实的地址和入口；示意图注明不可导航。

维护唯一行程主记录，正文、地图、预订、预算、摘要使用同一版本。阶段仅可标「草案 → 关键约束已查证 → 可进入预订 → 订单已整合 → 出发前已复核」；有关键缺口不得声称完全核实。定稿检查日期/星期/夜数/跨日航班一致、无重叠、硬衔接缓冲、开放与安检、参观正餐休息睡眠、版本一致、未知和备选。建议在预订前、出发前约 30 天/7 天/48 小时及使用前一日按风险复核；未实际设置不得声称自动提醒。旅行后实际体验与原计划分开记录，长期偏好只依据明确确认的变化更新。

## 分阶段交付

| 阶段 | 默认交付 | 必须帮助用户完成的判断或行动 |
|---|---|---|
| 发现 | 聊天精选提案 | 什么值得体验、为何契合、关键未知 |
| 路线决策 | 主路线与比较表，必要时地图 | 城市顺序、夜数、核心体验与取舍 |
| 准备预订 | 行动清单，可纳入主行程 | 先订什么、入口、日期、两人费用、条款、失败备选 |
| 完整规划 | 手机友好 HTML 主行程 | 概览、逐日执行、预算与待办 |
| 旅行现场 | 聊天短行动卡 | 下一站、交通、入口/导航、最晚行动时间与删减规则 |
| 局部修改 | 改动结果与直接影响 | 哪些改变、是否冲突、需要决定什么 |

开头先给推荐结论和必要决策；简单问题不生成全套文档。完整交付按「概览与紧急待办 → 当天使用 → 深读依据」组织，保留研究深度但不让长文淹没现场信息。

HTML 是唯一主行程；PDF 仅按需导出为带版本与日期的离线/打印快照。长篇餐饮、讲解可独立附件，主行程摘要并链接。研究依据与候选取舍保留在折叠块或相应记录，不展示全部搜索过程。主文件更新后，检查关联附件/导出物；未重导出的旧 PDF 明确过期版本，不称已同步。

## 交付结构与版式
完整行程 HTML/长文交付按固定顺序：封面（标题、日期、天数夜数、版本号＋阶段）→ 出发前待办 → 固定安排·行程锚点 → 逐日卡片 → 地图依据与精度说明 → 版本脚注；适配手机连续阅读和打印。生成 HTML 时以 `references/html-template.html` 为底稿，保留其 CSS，按注释复制重复块并替换全部 `{{占位符}}`，交付前确认无残留占位符。

**配色（可按目的地调整）**：`html-template.html` 的排版结构固定。**默认／优先**使用模板暖纸＋砖红主色：`--paper:#faf8f4`、`--accent:#94453c`（及配套 `--ink`／`--muted`／`--line`／`--green`）。**硬性禁止**用蓝色做旅行计划 HTML 的主色调：不得将 `--accent` 设为海蓝／雾蓝／各类蓝色，也不得把整页主调做成蓝色系（含海雾蓝、浅暖蓝纸等把页面洗成蓝调的做法）。若确需按目的地换主色色相，**只允许非蓝方向**（如苔绿／沙褐／雾紫），且**饱和度与明度须贴近 `#94453c`**（约 HSL 饱和度 ~42%、明度 ~41%），不要用发灰发淡、「低饱和到发雾」的主色。纸色仍避免灰底与霓虹高饱和；同一次行程内变量一致，导航背景使用同一 `--paper` 变量。文案宜写「默认模板暖纸＋砖红；禁止蓝主色；若换色相仅非蓝方向，饱和度对齐模板 accent」。勿为炫彩改动版式网格。

**出发前待办**分三级：01 最紧急（稀缺资格、硬交通）／02 出发前确认／03 机动安排。每项写：「对象｜动作」标题；电话或购票/预约入口；要问的具体问题；付款前须核对的点；末句「状态：未预约／未购票／已订…」。

**固定安排·行程锚点**列出排程须围绕的项目及其状态；说明「固定」只表示排程锚点，不代表已订。逐日卡片用链接回指相关锚点。

**逐日卡片**：日期＋星期、当日主题、路线链（A → B → C）；住宿条（酒店、第 N 晚、已订／未订／退房日）；当天固定项；当日逻辑说明（含触发规则）；逐时行程，每行带状态标签；交通分段估算（注明估算／公开时刻／待司机核）；地图。抵达跨午夜时单独写明实际入住为次日凌晨，并列入待办确认晚到保房。

**候选比较块**：每个候选一句定位（如动线优先、就近备选）、地址、已知与未核信息、选前要问的问题，整块标「仅候选，未选未订」。

## 版本
版本号用「V主.次」：结构或路线重排升主版本，局部更新升次版本。脚注写日期、本版改动、仍为草案的部分、未订项目和需按旅行日期复核的内容。

## 地图规范
地图北朝上；点位统一坐标系（中国境内统一为 GCJ-02，其他来源先转换），按当地纬度修正经度长度，横纵同一距离比例，并画比例尺和指北针。跨城与市区分开成独立面板，各自有比例尺。入口、店门、接车点未核实时不画成精确点，在图下列出未定位项及原因。每幅图注明「示意，虚线为行程连接非道路轨迹，不可导航」；文末「地图依据与精度说明」列出坐标来源、核对日期和精度局限。

## 模板使用与文件验收

现有行程优先原位局部修改，保留文件身份、既有样式与版本历史，不另建并列主文件。完整新行程使用本包 HTML 模板；模板决定呈现，不决定内容深度。可按需复用 anchor-list/anchor-card、event、details.sources 等组件加入住宿比较、预订、预算或备选，不改核心骨架/CSS、不硬塞无用模块。必要行动与关键风险不藏入默认折叠区。

### 内容与视觉主次

先按原有研究、决策与排程规则完成判断，再组织交付；不因页面长度、组件数量或模板空位减少研究、改变候选取舍或压缩必要体验时间。核心项目在正文交代具体地点、为什么值得去、现场重点及执行条件，篇幅随项目价值调整；简洁优先去重复和装饰，不删除重要介绍、时间、条件、例外与备选。长篇专业讲解可另附，正文仍保留现场够用的信息；未选优质候选及取舍继续按现有规则留存。

| 模板组件 | 使用规则 |
|---|---|
| `event`、内嵌 `icon` | 逐日体验是主体。图标选用模板 `icon-*`，旁边保留文字；可复制符号定义扩展，不依赖在线图标或本次私人文件。 |
| `stay-bar`、`status` | 住宿、晚数与状态紧凑呈现。来源/时间依据、核实程度、选择状态、预订状态分别表述；`is-booked` 仅用于确已预订，固定安排或本机勾选不构成预订证据。 |
| `note-warning`、`note-highlight`、`note-alternative` | 分别用于限制/风险、体验重点、备选触发；配明确文字标签，不仅靠颜色。按需使用，不把每段介绍都包装成提示框。 |
| `transport`、`transfer-route`、`mode`、`duration`、`clock` | 交通默认紧凑列表：路线与方式轻量标识，耗时/缓冲与钟点分色，估算或待核说明紧邻数值。写清钟点指抵达入口、完成寄存/报到还是发车，缓冲是否包含在耗时中；保留接驳、取行李与失败条件，不逐段做大卡片或重复图例。复杂换乘可增加必要说明，不设机械面积上限。 |
| `budget`、`anchor-list`、`details.sources` | 预算和候选按需呈现；研究依据可折叠，关键执行信息直接可见。无适用内容时移除整个可选模块，不填空泛文字。 |

保持住宿、交通、状态和来源的辅助地位；用间距、细分隔线、小图标及适量高亮帮助扫读，不用缩小正文、隐藏必要内容或截断文本换取紧凑。遵循模板的手机、桌面和打印样式；打印时展开必要说明与来源，不把屏幕折叠状态带入缺失的打印稿。

### 更新完整性

以本次工作材料或更新前主记录为基准，核对所选项目及其介绍、固定安排、待办、住宿、交通、预算、预订与备选的去向；合理合并重复，但删改实质内容须有本次授权或明确取舍原因。纯排版修改不得改写日期、钟点、时长、金额、状态与条件。局部内容更新只同步受影响模块，检查概览、逐日内容与行动清单一致，不重做无关研究。

交付前检查：

- 全部占位符已替换，HTML 转义正确，无孤立格式符号和可见模板说明；复制块后的 id、锚点和 data-check 唯一且一致。
- 手机窄屏和桌面布局无横向溢出、遮挡；导航可到对应日期，折叠可开关，勾选仅作用户本机待办标记，不代表已下单或已同步到主记录。
- 以同一份规划材料核对交付内容，重要介绍、执行条件及模块无无故丢失；日程主体清晰，交通保持紧凑，长地名、多条提醒和复杂接驳仍可读。排版优化不改变研究深度及选项取舍。
- 链接和附件目标正确；地图须替换模板示例几何并核实位置，资料不足时移除示例图并说明未定位项，不能只换地点文字。
- 打印/离线版本不截断关键内容；导出 PDF 前展开或转为可打印的必要说明，不能把 HTML 中被打印样式隐藏的内容误称为已导出。日期、夜数、状态、正文、地图、预算和版本一致。
- 实际检查手机布局与交互后才称通过视觉/功能验收；工具不可用时说明未验证项，结构检查不能冒充实测。保存成功后再提供链接，失败明确报告，遵守平台存储规则。
