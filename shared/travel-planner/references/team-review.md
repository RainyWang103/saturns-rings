# 行程整合、验收与修正

职责划分不代表存在其他 Bot；仅在宿主支持且获得适当授权时委派，无协作机制则由当前助手自检并修正自己的草稿。遵守平台授权与保存边界，不声称独立验收或后台通知。

## 专项输入与整合边界

| 专项 | 规划师提供 | 规划师验收 |
|---|---|---|
| 餐饮 | 日期、区域、餐次、时间窗、预算、饮食限制和已定选择 | 门店身份、开放/用餐时长、动线、预约与核实状态、预算和备选是否适配 |
| 文化讲解 | 目标场所、参观日期、主题与停留窗口 | 观看顺序、开放限制、内容与参观窗口是否合理，待核信息是否标明 |
| 归档交付 | 当前主文件、目标位置、版本与获授权改动 | 文件身份、链接、正文/地图/预算/摘要版本一致，无并列主版本 |

餐饮发现、品质判断、推荐数量、来源策略和专业输出由餐饮技能负责；不在旅行层重复规定或覆盖其方法。讲解深度与证据由讲解技能负责；重要内容需要更多时间时先调行程，不能仅为塞满日程压缩核心体验。已排除项未经新证据或新要求不得悄悄恢复。

候选可进入明确标为候选的比较块，但不能伪装为已选、已核或已订。遇到冲突提出具体调整需求，不擅自改写专项定稿；自行产出的草稿可在任务授权内修正，不因没有专项 Agent 停止完成工作。归档不自动删除或移动原文件。

## 每次可审交付的检查

1. **质量**：有明确主张及取舍，核心特色和用户兴趣无明显遗漏，无重复堆砌；优质未入选候选有保留理由。
2. **事实**：目标日期、来源与核验状态可追溯，候选/估算与已订分开；未公布或冲突不冒充确认。
3. **衔接**：日期、夜数、门到门时间、预约到场、参观用餐休息及硬截止可执行；必要备选与删减触发条件明确。
4. **交付**：符合当前阶段，待办可执行；文件检查遵循交付规则，所有摘要与主记录一致，无私人资料泄露。

检查范围跟随本次产物：专项检查相关事实与适配，完整规划统一检查全部硬约束；局部修改检查受影响内容及下游，不重复验收未变且已通过的模块。记录本次检查对应的主记录版本；新证据、内容变化或依赖变化使相关检查失效。最终 HTML 的内容保留、视觉与交互检查统一遵循 [交付规则](deliverables.md)，无需再跑第二套相同检查。文件通过不代表研究通过；不能通过删内容或压缩体验来消除检查失败。

先自检再向用户交付；对用户明确请求的验收或收到专项交付，先给「通过（范围）」或「需修正（1–5 条：缺什么、改哪里、成功标准）」。普通成品无需附冗长检查表。

## 回退与轮次

事实缺口回执行核实，时间动线冲突回排程，核心项目不可行回路线决策，表达/版式问题只改交付。新版本在当前任务中复验受影响项；同一缺口连续两次尝试仍无新证据或可行调整，报告具体阻塞与替代，不空转。该限制不禁止修正明确的小错误，也不降低验收标准。未收到的未来版本不承诺自动监控。
