## 计时口径与验收

保存脱敏运行记录：版本SHA、场景、模型/推理设置、工具条件、起止时刻、事件类型、耗时、失败原因、范围键。范围键对应对象/字段/日期/条件，不存私密原文、订单号或凭证。计时来自宿主日志或人工标记；不可观测项记“未知”，不推算模型思考时间。

| 指标 | 采集与计算 |
|---|---|
| 首次有用响应 | 请求提交→首次能帮助决策的结果/明确关键缺口；“正在处理”不算 |
| 总耗时 | 提交→完整交付且必要检查结束；保存任务要等成功。单列用户等待与人工干预次数，不偷偷扣除 |
| 模型耗时 | 仅用宿主暴露的调用时长；墙钟减工具时间不等于纯推理时间 |
| 工具/搜索 | 调用次数、各调用时长及累计时长；并行累计可大于墙钟。查询条数与工具调用数分别计 |
| 无必要重复搜索率 | 无新条件/新证据/必要交叉核验/重试理由的重复查询数÷查询总数；逐条判定，不能仅按词串 |
| 文件读取量 | 调用次数、实际读取字节/可得token、重复同版本读取；目录元数据与全文分开 |
| Token/费用 | 使用服务实际返回账单/用量；App不可见时写未知，不按API价估算套餐成本 |
| 质量 | 事实错误数/已审关键事实数；遗漏硬约束数/输入硬约束数；两者列出分母与未审范围 |
| 文件/回归 | 成功交付文件数/要求文件数、HTML检查通过数/已执行数；没跑不算通过；附失败详情 |

首轮验收先要求关键事实/硬约束/既有内容无退化，自动化全绿。端到端提速以同条件配对中位数衡量，暂以完整任务减少20%为试验目标，非已实现承诺；首次有用结果与尾部慢例也不得明显恶化。未拿到在线基线前，只能报告调用/读量变化与机制验证，不发布“快了多少”的结论。初期无须加数据库、计费API或后台遥测。
