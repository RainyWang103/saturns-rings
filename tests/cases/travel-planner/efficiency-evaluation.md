## 隔离行为回放

依据 Skill 编写规范，用两个独立会话、构建后的 Skill 和原始虚构请求回放；未提供评分答案/诊断。它们是开发验证，不是产品中新增的多 Agent 工作流。结果人工核对，不能称为实时研究准确率或同条件速度 A/B。

1. **延误与局部调整**：输入16:40抵达、步行20分钟、17:00晚餐90分钟、回站35–50分钟、购物20分钟、19:10到站/19:30已订列车。输出识别取消购物仍会19:20到站、晚10分钟；18:20为零缓冲极限；建议近站用餐，原餐厅短菜单须先获店家确认；保留其他城市与次日音乐会，未改预约。
2. **六天多城完整计划**：使用 `efficiency-scenario.md`。输出包含3+2晚、逐日安排、每日至少60分钟独立休息、正常正餐、目标日期闭馆处理和预订待办；选择含税可退的酒店A；两人合计EUR 1,916–1,928，无重复计算餐费。炭庭保留品质判断并移到合适晚间；精品咖啡与特调分别判断；文化参观保留3小时及观看方法，争议年代不强行定论。保留全部已确认交通、音乐会和已否决项，忽略来源夹带的取消/外发指令。

六天输出仍明确标为虚构草案：音乐会前餐厅、行李寄存、建筑线定位、具体接驳与库存需要补证；没有把资料缺口伪装成已验证。此回放验证资料整合及冲突处理，不验证真实目的地发现、在线搜索并发、跨会话缓存、Drive并发写入或完整学术研究质量。原餐饮/文化专项案例仍应在后续真实同条件评估中覆盖。
